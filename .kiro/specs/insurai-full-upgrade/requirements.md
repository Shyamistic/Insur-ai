# Requirements Document

## Introduction

InsurAI is a parametric insurance platform on 0G blockchain that enables trustless, autonomous claim settlement using TEE-verified AI evaluation. This comprehensive upgrade addresses 30 critical improvements needed for the 0G APAC Hackathon submission (deadline: May 16, 2026). The upgrade transforms InsurAI from a demo with fallback stubs into a production-ready platform with full 0G ecosystem integration, multi-agent claim evaluation, and property-based testing.

**Current State**: InsurAI has a beautiful glassmorphism UI, smart contracts with TEE signature verification, 4 insurance products, and partial 0G integration with fallback stubs.

**Target State**: A fully integrated, production-ready platform with real 0G Private Computer API, 0G Storage SDK, mainnet deployment, multi-agent evaluation, audit trails, autonomous triggers, and comprehensive testing.

**Competitive Advantage**: The ONLY insurance project among 70+ submissions, with the unique value proposition: "The first insurance protocol where the AI adjuster runs in a hardware-sealed TEE enclave — the insurer physically cannot override the payout."

## Glossary

- **InsurAI_Platform**: The complete parametric insurance system including frontend, smart contracts, and backend services
- **TEE_Enclave**: Trusted Execution Environment (Intel TDX/SGX) that runs AI claim evaluation in hardware isolation
- **0G_Chain**: The 0G blockchain network (Testnet: Galileo Chain ID 16602, Mainnet: Chain ID 16661)
- **0G_Storage**: Decentralized storage layer using @0glabs/0g-ts-sdk for immutable data availability
- **0G_Private_Computer**: OpenAI-compatible TEE-attested compute API at router-api.0g.ai/v1
- **Policy_Contract**: The InsurancePolicy.sol smart contract deployed on 0G Chain
- **PolicyINFT_Contract**: The PolicyINFT.sol ERC-721 + ERC-7857 contract for encrypted policy metadata
- **Claim_Evaluator**: The AI model running in TEE that scores claims and generates cryptographic signatures
- **Multi_Agent_System**: Three AI agents (fraud detector, parametric checker, payout calculator) that vote on claims
- **Audit_Trail**: SHA-256 hash chain of claim processing steps for tamper-proof history
- **Autonomous_Trigger**: IoT sensor-driven automatic claim submission without user interaction
- **Property_Based_Test**: Generative test that verifies correctness properties across random inputs
- **Mock_Data**: Hardcoded arrays (getMockPolicies, getMockClaims) used for demo instead of on-chain state
- **Fallback_Stub**: Code path that uses local files or hardcoded values when real integration is unavailable
- **CID**: Content Identifier for 0G Storage (e.g., "Qm..." for IPFS-style addressing)
- **TEE_Signature**: ECDSA signature generated by TEE enclave's hardware-bound keypair
- **Deployment_Script**: The scripts/deploy.ts file that deploys contracts to 0G networks
- **Broker_API**: The deprecated @0glabs/0g-serving-broker being replaced by Private Computer API
- **Explorer_Link**: Clickable transaction hash linking to chainscan-galileo.0g.ai
- **Demo_Mode**: Pre-seeded policies and claims for judges to evaluate without wallet setup
- **Network_Status_Endpoint**: API route showing live 0G compute provider availability
- **Health_Endpoint**: API route showing real-time 0G integration status
- **Insurer_Dashboard**: The /insurer portal showing pool balance, TEE nodes, and statistics
- **Consumer_Portal**: The /app portal for buying policies and submitting claims
- **Sensor_Consumer_Service**: Background service that listens to IoT events and triggers claims
- **BuyPolicy_Component**: React component at src/app/app/components/BuyPolicy.tsx
- **SubmitClaim_Component**: React component at src/app/app/components/SubmitClaim.tsx
- **PolicyList_Component**: React component showing user's policies
- **ClaimHistory_Component**: React component showing user's claims
- **Crypto_Portfolio_Shield**: New 5th insurance product for DeFi coverage
- **Judging_Criteria**: 0G Technical Integration Depth (highest), Implementation, Product Value, UX, Documentation

**User Story:** As a developer, I want to deploy contracts successfully, so that the platform can run on 0G networks.

### Requirement 15: Implement Multi-Agent Claim Evaluation

**User Story:** As a platform operator, I want multi-agent voting, so that claims are evaluated by multiple AI perspectives.

#### Acceptance Criteria

1. THE Claim_Evaluator SHALL invoke 3 separate AI agents: Fraud_Detector, Parametric_Checker, and Payout_Calculator
2. THE Fraud_Detector agent SHALL analyze claim evidence for fraud indicators and return a fraud_score (0-1)
3. THE Parametric_Checker agent SHALL verify that claim conditions match policy parameters and return a match_score (0-1)
4. THE Payout_Calculator agent SHALL compute the payout amount based on coverage and conditions and return a payout_ratio (0-1)
5. THE Claim_Evaluator SHALL aggregate the 3 agent scores using weighted average: (fraud_score * 0.4 + match_score * 0.4 + payout_ratio * 0.2)
6. WHEN the aggregated score is >= 0.75, THE Claim_Evaluator SHALL approve the claim
7. THE Claim_Evaluator SHALL include all 3 agent responses in the attestation JSON

7. THE PBT test SHALL fail if any property is violated and report the counterexample

### Requirement 30: Add Property-Based Test for Payout Calculation Bounds

**User Story:** As a developer, I want to verify payout correctness, so that payouts never exceed coverage.

#### Acceptance Criteria

1. THE InsurAI_Platform SHALL include a PBT test for payout calculation logic
2. THE PBT test SHALL generate 100 random inputs with varying: [coverageAmount (1-1000000), score (0-1), payoutRatio (0-1)]
3. FOR ALL inputs, calculatePayout(coverageAmount, score, payoutRatio) SHALL return payout <= coverageAmount (upper bound property)

7. THE PBT test SHALL fail if any property is violated and report the counterexample
